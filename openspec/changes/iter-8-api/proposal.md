# Proposal: Iteration 8 — FastAPI Backend and Service Lifecycle

## Why

ChronoTrace has deterministic analytics (Iteration 5), a validated MCP server with five tools (Iteration 6), and a model client with evidence-first tool-calling loop (Iteration 7), but no stable HTTP interface exists for CLI (Iteration 10) and web UI (Iteration 11) clients. Without a FastAPI backend that owns application lifespan, validates configuration and dependencies at startup, exposes typed health/readiness/repo/chat/report endpoints with thin routed handlers, tracks long-running ingestion jobs without blocking the event loop, and shuts down cleanly, downstream consumers would embed business logic or bypass validation, and `chronotrace up` would have nothing to wait for on readiness.

Iteration 8 delivers that backend as the single coordinating HTTP layer between CLI/UI and the core services (config, graph, ingestion, analytics, MCP client, agent), with a distinct health vs readiness contract, observable job tracking, and clean resource teardown.

## What Changes

- **FastAPI application and lifespan** — Create `src/chronotrace/api/main.py` with `FastAPI` app and `lifespan` (`@asynccontextmanager`) that on startup: loads and validates `chronotrace.yml` via Iteration 1 `load_config` (no re-parsing YAML/env elsewhere), validates required directories (`data_dir`, `repositories_dir` — expand, create, writability probe), verifies Neo4j connectivity (`graph.verify_connectivity` / driver `verify_connectivity` against `graph.uri`/`database`), verifies required model config presence before declaring agent-ready, initializes shared `GraphGateway`/driver, `AnalyticsService`, `McpClient`, and `Agent` with controlled lifecycles; on shutdown: closes Neo4j driver, MCP client, and any agent HTTP/model clients cleanly, drains in-flight requests with timeout. Startup failure when required config or a hard dependency is unavailable aborts app startup (not a degraded-ready). `src/chronotrace/api/dependencies.py` provides DI (dependency-injected singleton config, graph, analytics, agent) for routes.
- **Typed request/response schemas** — Define `src/chronotrace/api/schemas/` with Pydantic v2 models for every endpoint: health/readiness, repository registration, repository status/listing, chat, report, job status, error envelope. All schemas enforce strict validation (reject unknown fields where appropriate), document field constraints, and never include secrets, connection strings, or raw Cypher.
- **Health and readiness endpoints** — `GET /health` returns process liveness (`status: ok`, uptime/version) with no dependency checks; `GET /ready` (or `/readiness`) returns dependency health (`status: ready|not_ready`, per-dependency `neo4j: ok|unavailable`, `config: ok`, `agent: ok|degraded|max_unavailable`) and is the probe `chronotrace up` / Compose `healthcheck` waits for. The two have distinct meanings and distinct HTTP status codes (200 vs 503).
- **Repository registration/ingestion endpoint** — `POST /repositories` (or `/api/repositories`) validates a Git URL (non-empty, http/https/ssh URL shape, no shell interpolation), registers the repository via ingestion service, and triggers ingestion **without blocking the event loop** (background task / `BackgroundTasks` or `asyncio.create_task` with job registry). Returns `201` with `{repository_id, job_id, status: queued|running}` and a pollable location/header (`job_id` for status endpoint). Rejects malformed URLs with `422` structured error.
- **Repository status and listing endpoints** — `GET /repositories` lists known repositories with `{repository_id, url, ingestion_status, last_ingested_at, head}`; `GET /repositories/{repository_id}` (and/or `GET /jobs/{job_id}`) returns job state machine (`queued|running|completed|failed`) plus `progress` (stage, percent where available), `started_at`/`finished_at`, `error` (actionable, no secrets) and repository metadata. Observable without polling the graph directly.
- **Chat endpoint** — `POST /chat` (or `/api/chat`) with `{repository_id, question, conversation_id?}` validates repository association (explicit `repository_id` required, non-empty, known repo), forwards to `Agent` via `McpClient` tool loop, respects iteration limits and timeout, and returns `{answer, citations: [{path, commit_hash, date, score}], evidence, limitations, conversation_id}`. Provider/model failures surface as structured `503`/`504` with retry hint, not fabricated answers. Deterministic fallback is not required here — chat is LLM-dependent.
- **Report endpoint** — `POST /reports` (or `GET /reports?repository_id=&file=`) validates `repository_id` + `file_path` (POSIX-relative, traversal-rejected via shared validators), invokes analytics/report service directly (no LLM), and returns the Iteration-5 common contract `{status: ok|insufficient_history|not_found, repository_id, target, result:{score, breakdown, rankings}, evidence, limitations}`. Works when the model is unavailable.
- **In-app job tracking** — In-memory (or lightweight persisted) `JobStore` (`src/chronotrace/api/jobs.py`) tracking ingestion jobs: `job_id` (UUID), `repository_id`, `status` enum (`queued`, `running`, `completed`, `failed`), `stage` (`CLONING|EXTRACTING|FILTERING|WRITING_GRAPH|COMPLETED|FAILED`), `progress`, `error`, `created_at`/`updated_at`. Thread/async-safe (lock or `asyncio.Lock`), bounded registry (eviction policy documented), and queried by both repo-status and job-status endpoints. Polling is the MVP; no WebSocket/SSE push.
- **Thin routes** — Route handlers in `src/chronotrace/api/routes/` (`health.py`, `repositories.py`, `chat.py`, `reports.py`) contain only validation, auth/context wiring, service delegation, and response shaping; no Cypher, no scoring formulae, no Git subprocess logic, no model prompt construction. Business logic stays in `core/ingestion`, `core/analytics`, `core/graph`, `agent/`, `mcp_server/`.
- **Structured errors and validation** — Every `4xx`/`5xx` uses a shared error envelope `{error: {code, message, details?}, request_id?}` with actionable messages, no secret leakage, and consistent HTTP codes (`400`/`422` validation, `404` not_found, `503` not_ready/graph_unavailable/model_unavailable, `500` internal). FastAPI `RequestValidationError` and `HTTPException` handlers produce the envelope. Request validation rejects malformed JSON, missing required fields, extra unknown fields (where strict), and oversized payloads.
- **Non-blocking ingestion and observability** — Ingestion work runs off the request thread (FastAPI `BackgroundTasks` or `asyncio.to_thread`/`create_task`); the request returns immediately with `job_id`. Event-loop blocking is avoided (no synchronous `subprocess.run` or heavy `pydriller` iteration on the event loop without `to_thread`). Job progress is exposed; a failed ingestion does not mark the repository as successfully updated.
- **Clean shutdown** — Lifespan shutdown closes Neo4j driver (`driver.close()`), MCP client (`mcp_client.close()`), `httpx`/`model` clients, and cancels/awaits background jobs with timeout. No leaked sessions; subsequent requests after shutdown draining receive `503`.

## Capabilities

### New Capabilities

- `api`: FastAPI backend and service lifecycle — application factory and lifespan (startup config validation, directory verification, Neo4j/model readiness checks, shared driver/analytics/MCP/agent initialization, graceful shutdown), typed request/response schemas for health/readiness/repositories/jobs/chat/reports with strict validation, `GET /health` vs `GET /ready` distinct contracts, repository registration triggering non-blocking ingestion with pollable job tracking (`JobStore` with `queued|running|completed|failed` and stage/progress), repository listing/status endpoints, chat endpoint delegating to agent with repository-scoped evidence-grounded responses, report endpoint serving deterministic analytics without LLM, thin route handlers delegating to core services, structured error envelope, conversation/repository association, secret non-exposure, and event-loop non-blocking guarantees.

### Modified Capabilities

- None — no existing shipped spec capability changes requirements. Iterations 0–7 (foundation, config, graph, ingestion, static analysis, analytics, MCP, agent) are consumed as libraries through their public Python APIs. Config is read via Iteration 1 validated object; graph via Iteration 2 driver; analytics via Iteration 5; MCP via Iteration 6 SDK client; agent via Iteration 7 client. This change is additive and owns the HTTP boundary.

## Impact

- **New code**: `src/chronotrace/api/` — `main.py` (FastAPI app + `lifespan`), `dependencies.py` (DI singletons), `schemas/__init__.py` + per-endpoint schemas (`health.py`, `repositories.py`, `jobs.py`, `chat.py`, `reports.py`, `errors.py`), `routes/__init__.py` + `routes/health.py`, `routes/repositories.py`, `routes/chat.py`, `routes/reports.py`, `jobs.py` or `services/jobs.py` (`JobStore`, `Job` model), optional `services/repository_service.py`, `services/report_service.py` thin orchestrators. No new node/relationship types; no schema migration.
- **Existing modules**: Consumes `src/chronotrace/config` (validated `ChronoTraceConfig` and `validate_startup`), `src/chronotrace/core/graph` (driver lifecycle, repository isolation, parameterized Cypher), `src/chronotrace/core/ingestion` + `core/analytics` (pure-Python services), `src/chronotrace/mcp` (client), `src/chronotrace/agent` (agent + model client). No changes to their contracts required; if minimal adapters are needed (e.g., ingestion progress callback), they are additive and backward compatible.
- **Dependencies**: `fastapi`, `uvicorn[standard]`, `pydantic`, `httpx` already in `pyproject.toml` (verify versions); no new external runtime dependency required. Optional `python-multipart` only if file upload is used (not required for MVP URL-based ingestion).
- **Configuration**: Reads `project.data_dir`, `project.repositories_dir`, `graph.uri`/`database`/`batch_size`, `analysis.history.decay_half_life_days`, `agent.provider`/`model`/`reasoning_effort`, and secrets `MODEL_API_KEY`/`NEO4J_USERNAME`/`NEO4J_PASSWORD` via the Iteration 1 loader — revalidates at startup, does not re-parse YAML/env in routes. New optional `api.host`/`api.port` keys (Pydantic-validated with defaults `127.0.0.1`/`8000`, unknown-key rejection) may be added under validated config.
- **Docker/Compose (deferred)**: Iteration 9 will add `agent-api` service reusing the backend image with `command: ["uvicorn", "chronotrace.api.main:app", "--host", "0.0.0.0", "--port", "8000"]`, container-to-container Neo4j host `neo4j` vs `localhost` for CLI, and data volume mounts for `data_dir`/`repositories_dir`. This iteration makes the app runnable directly (`uvicorn chronotrace.api.main:app`) and testable without Compose.
- **Downstream**: Unblocks Iteration 9 (Docker images + Compose wiring), Iteration 10 (CLI `add`/`chat`/`report`/`status`/`up` via `httpx` `api_client.py`), Iteration 11 (web UI via same HTTP contracts), and Iteration 12 (API integration/e2e tests, backtesting via report endpoint).
- **Security/compliance**: Request validation boundary at HTTP layer (URL shape, POSIX path traversal rejection, bounded payload limits); error envelope redacts secrets; no `MODEL_API_KEY`/`NEO4J_PASSWORD`/connection strings in responses or logs; parameterized Cypher stays behind graph layer; chat evidence must still be traceable to tool output (Iteration 7 evidence-first policy preserved via agent delegation).

## Out of Scope (Explicitly Excluded)

- Docker image build, `docker-compose.yml` `agent-api`/`mcp-server` services, named volumes, and container-to-container hostnames (Iteration 9).
- CLI commands `chronotrace init`/`up`/`down`/`status`/`add`/`chat`/`report` consumption of these endpoints (Iteration 10) — this iteration ships the server, not the CLI client (a throwaway `httpx` smoke client suffices for the gate).
- Web UI chat/report/graph presentation (Iteration 11).
- Authentication/authorization beyond local trust boundary (no JWT/OAuth in MVP); rate-limiting and request signing deferred.
- WebSocket/SSE push for job progress (polling only in MVP); pagination/cursor beyond `limit`/`offset` in listing endpoints (basic bounded listing suffices).
- SZZ, function/symbol-level tracking, real coverage, embeddings, multi-language parsing, backtesting (PLAN §7 exclusions, Iteration 12).
- Hot-reload of `chronotrace.yml`; config changes require restart.

## Acceptance Criteria (Iteration-level)

Maps to PLAN §6 Iteration 8 Scope, Suggested HTTP capabilities, Acceptance criteria, and Completion gate:

- API startup fails fast (process exit / failed lifespan) when required configuration is invalid or required directories are not writable, and when Neo4j or required model configuration is unavailable for dependent services — the app does not report ready in those cases.
- `GET /health` and `GET /ready` have distinct meanings: health is process liveness (no dependency checks); readiness reflects dependency health (`neo4j`, `config`, `agent`) and returns `503` when not ready. Tests assert both endpoints independently.
- Request validation rejects malformed inputs: invalid Git URL, missing `repository_id`, traversal `file_path` (`../`, absolute), malformed JSON, extra unknown fields (where strict), and oversized payloads — each returns the structured error envelope with actionable message and correct HTTP code, no secret leakage.
- `POST /repositories` validates the Git URL, triggers ingestion without blocking the event loop (request returns in < 500 ms even for large repos in mocked test), returns `job_id`, and job state is observable via `GET /repositories/{id}` and/or `GET /jobs/{job_id}` through `queued → running → completed|failed` transitions; a failed ingestion does not mark the repository as successfully updated.
- `POST /chat` validates `repository_id` is present and known, invokes the agent (delegates to `McpClient` + model), respects iteration limits/timeouts, and returns an evidence-grounded response with citations/evidence/limitations and `conversation_id`; model-unavailable returns structured `503`/`504`, not a fabricated answer.
- `POST /reports` (or equivalent report GET) works without an LLM — validates `repository_id` + `file_path`, calls analytics directly, and returns the common contract `{status, repository_id, target, result, evidence, limitations}` with `insufficient_history` vs `not_found` distinguished.
- API routes are thin: handlers contain only validation and service delegation; no Cypher, no scoring formulae, no direct Git subprocess, no model prompt logic. Verified by code review and by unit tests that mock services.
- Job tracking is async-safe and bounded: `JobStore` handles concurrent creates/updates/reads; registry has a documented eviction/limit policy; tests cover concurrent job creation and polling.
- Clean shutdown: `lifespan` shutdown closes Neo4j driver, MCP and model clients, and drains in-flight work; tests assert `driver.close()`/`client.aclose()` called and no leaked sessions (session context managers exercised post-shutdown raise).
- Tests for success, invalid requests, dependency failure (mock unavailable Neo4j/model), and shutdown cleanup pass (`pytest` for `tests/unit/api` + `tests/integration/api`).

## Dependencies and Sequencing

- **Depends on**: Iteration 1 (validated `chronotrace.yml` + startup validation), Iteration 2 (Neo4j driver lifecycle, session/transaction hygiene, repository isolation, parameterized Cypher), Iteration 3 (stable `repository_id`, ingestion pipeline and `STAGE` enum), Iteration 4 (import graph, path canonicalization), Iteration 5 (analytics result contract and four operations), Iteration 6 (MCP server + `McpClient` consumed by agent), Iteration 7 (agent + `ModelClient` with tool-calling loop and iteration limits). CLI/API must not re-implement any of those layers.
- **Unblocks**: Iteration 9 (Docker `agent-api` image + Compose `healthcheck`/`depends_on` against `GET /ready`), Iteration 10 (`chronotrace add` → `POST /repositories`, `status` → `GET /repositories`, `chat` → `POST /chat`, `report` → `POST /reports` via `cli/api_client.py`), Iteration 11 (web UI via same contracts), Iteration 12 (full-stack integration/e2e and hardening).
